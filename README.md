# 金鑰鍊成器 × 賽博符咒

一款結合「道家符咒 × 賽博安全」視覺概念的密碼產生器與本機加密密碼庫。

> 本作品為作品集 MVP（最小可行產品），用於展示產品設計、前端實作與 AI 協作開發流程；尚未經過獨立資安稽核，不建議用來保存金融、政府帳號等高價值憑證。

## 線上體驗

[開啟金鑰鍊成器 × 賽博符咒](https://merle1022.github.io/cyber-talisman-key-forge/)

## 為什麼做這個作品？

最初的想法來自一個很生活化的觀察：大家知道密碼應該更長、更複雜，卻常因為難記、難管理而重複使用簡單密碼。

我先製作密碼產生器，後來進一步思考：「產生了這麼長的密碼，使用者要放在哪裡？」因此加入本機加密密碼庫、備份與復原流程，並把自己原本的「道家符咒封印」概念延伸成完整體驗。

「符咒」在這裡不是安全技術，而是視覺與互動隱喻：產生密碼像鍊成金鑰，保存密碼像加密封印。真正的資料保護仍由瀏覽器的加密 API 完成。

## 我的角色與開發方式

這是一個 AI 協作開發作品。

我負責提出產品概念、觀察使用問題、決定功能方向、測試手機與電腦操作，並持續提出修改意見；AI 協助把需求轉換成介面、程式碼、加密流程與部署設定。每一輪都從實際試用出發，例如：

- 發現一般隨機密碼不容易記憶，因此增加易讀密碼與中文記憶短語。
- 發現產生密碼後仍需要保存，因此整合本機密碼庫。
- 發現輸入密碼時無法確認內容，因此加入顯示／隱藏按鈕。
- 發現只保存於瀏覽器仍可能遺失，因此加入加密備份、匯入與紙本復原卡。
- 發現復原卡的技術文字不易理解，因此重新改寫成一般使用者能操作的說明。

這個過程讓我練習的重點不是「一次寫出所有程式」，而是把模糊想法整理成需求、透過測試發現問題，並與 AI 反覆協作完成可使用的產品。

## 主要功能

- 三種金鑰模式：高強度亂碼、易讀金鑰、中文記憶短語
- 自訂長度與字元組合
- 使用安全亂數產生金鑰
- 密碼強度與估算資訊
- 本機加密密碼庫
- 新增、編輯、刪除、搜尋、分類、顯示與複製紀錄
- 閒置五分鐘自動上鎖
- 加密 JSON 備份匯出與匯入
- 紙本復原卡與操作說明
- 手機、平板與電腦響應式版面
- PWA：可加入主畫面並支援離線開啟
- 「鍊／封」賽博符咒互動動畫

### 亂數與加密

- `crypto.getRandomValues()`：產生密碼與加密所需的安全亂數
- Web Crypto API：在瀏覽器中執行加解密
- PBKDF2 + SHA-256：由總管法印推導加密金鑰，迭代 310,000 次
- AES-GCM 256-bit：加密密碼庫內容並驗證資料完整性
- 每次加密使用隨機 salt 與 IV

總管法印本身不會儲存在網站或資料庫。密碼庫資料經加密後存於目前瀏覽器的 `localStorage`；網站沒有 Email 找回機制，也不會自動跨裝置同步。

## 備份與復原觀念

恢復密碼庫必須同時具備：

1. 匯出的加密 JSON 備份檔。
2. 建立密碼庫時使用的總管法印。

少了任何一項都無法恢復。紙本復原卡只是協助記錄與操作的說明，本身不包含密碼庫資料。

## 手機與電腦之間如何搬移？

目前沒有即時同步功能，必須使用加密 JSON 手動搬移：

1. 在目前裝置完成修改後，匯出最新的加密備份。
2. 將備份放入有兩步驟驗證的私人雲端空間，或使用加密 USB 搬移。
3. 在另一台裝置下載並匯入該 JSON，再用原本的總管法印解鎖。
4. 如果在第二台裝置修改資料，必須重新匯出，其他裝置才拿得到新版。

匯入會覆蓋該裝置現有的本機密碼庫，不會自動合併兩台裝置的修改。建議指定一台主要裝置、依日期保留版本，並在匯入前確認哪一份最新。加密備份可以放在私人雲端，但不要放進公開 GitHub Repository。

## 本機執行

需要 Node.js 22.13.0 以上版本。

```bash
npm install
npm run dev
```

正式建置檢查：

```bash
npm run build
```

## 已知限制

- 尚未接受第三方資安稽核或滲透測試。
- 資料只存在目前瀏覽器，清除網站資料可能造成密碼庫遺失。
- 沒有帳號、Email 找回、雲端同步或多人共享。
- 沒有瀏覽器擴充功能及網站自動填入功能。
- 尚未支援生物辨識、Passkey 或外部硬體金鑰。
- PWA 離線快取不等於密碼資料已完成備份。
